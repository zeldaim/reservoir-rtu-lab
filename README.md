# iot-doorlock-lab — 스마트 도어락 보안 관제

ESP32 도어락(Wokwi 시뮬레이터)과, 그 도어락을 지키는 관제 서버.
임베디드프로그래밍(아두이노) 과제 + 포트폴리오 — 성적이 나오기 전까지 비공개.

```
도어락 (ESP32 · FreeRTOS)                       관제 서버 (PC · Docker)
 비밀번호 · 레이트 리밋 잠금 · 배회 감지   ──▶   nginx 레이트 리밋 · 차단 목록
 사건 기록 (HMAC 서명)                          API (기기 토큰) — BOLA 시연·수정
 서명된 업데이트만 적용                         탐지: 룰(명세에서 자동 생성) + ML
 LCD 에 AI 요약 · 부저                   ◀──   AI 사고 리포트 · 자동 대응(차단 · 기기 잠금)
```

## 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 도어락 본체: 비밀번호 · 레이트 리밋 잠금(60초 5회 → 30초, 반복 시 2배) · 배회 감지 · 사건 기록 | ✅ 컴파일 확인 |
| 2 | **FreeRTOS 작업 분리** — 느린 통신 중에도 입력이 멈추지 않게. 분리 전 · 후 입력 지연 측정 | 진행 중 |
| 3 | 관제 서버 + 사건 전송(HMAC 서명) + AI 사고 리포트 (API 키는 서버에만) | |
| 4 | 서버 ML — 레이트 리밋 아래 느린 무차별 대입 탐지, 레이트 리밋과 비교 표 | |
| 5 | API 보안 — `/devices/{id}/events` BOLA 시연 → 수정 → 탐지 · 서버 레이트 리밋 | |
| 6 | API-BOM (명세 + 관측 트래픽으로 API 목록 · 숨은 API) · 명세에서 탐지 룰 자동 생성 · CI 룰 시험 | |
| 7 | 자동 대응 — 경보 → 플레이북 (출발지 차단 · 기기 원격 잠금 · 알림) | |
| 8 | 공급망 — 라이브러리 버전 고정 · 펌웨어/서버 SBOM · 취약점 검사 · CI 빌드 서명 · 기기가 서명된 업데이트만 적용 | |
| 9 | (선택) 기기 ML — 키 입력 리듬으로 주인 판별 (TinyML) | |
| 10 | 개발 문서(PDF) · 시연 영상(5~10분) | |

## 실행 (단계 1~2)
- **Wokwi:** wokwi.com → New Project → ESP32 → `firmware/doorlock/` 의 `doorlock.ino`(→ sketch.ino) · `diagram.json` · `libraries.txt` 붙여 넣기 → ▶
- **컴파일만 (로컬):** `arduino-cli compile --fqbn esp32:esp32:esp32 firmware/doorlock`

## 알려 둘 제약
- Wokwi 웹의 가상 Wi-Fi 는 **인터넷으로만** 나간다. 내 PC(localhost)로 들어오는 Private Gateway 는 유료 기능이라, 3단계 서버 연결 방식은 따로 정한다.
- Wokwi 공개 게이트웨이는 트래픽을 모니터링한다 — 실제 비밀값은 보내지 않는다.
