# KISA 체크리스트 — 이 프로젝트 적용성 1차 초안 (2026-11-25)

출처: `docs/data/kisa_checklist.json` (KISA 2026년판, 118개 항목). **이 문서는 Claude 가 항목 제목만 보고 분류한 1차 초안이다.** 점검 내용·판단 기준 전문은 옮기지 않았고, 사람이 검토하기 전까지 제출 문서에 그대로 쓰면 안 된다.

## 왜 UNIX 뿐 아니라 제어시스템(C-*) 섹션도 쓰는가

서버는 Linux 컨테이너, 장치는 "제어시스템"(무인 배수지 RTU)이다. UNIX 섹션(U-01~67)은 서버 쪽에만 맞고, 범용 서버 하드닝 항목이 많아 이 프로젝트의 핵심(장치·공정 보안)과는 거리가 있다. **제어시스템 섹션(C-01~51)이 오히려 이 프로젝트의 주제와 직접 맞는다** — 아래 "강하게 맞음" 항목이 그 근거다.

## 강하게 맞음 (이미 구현·측정된 것과 1:1)

| 코드 | 제목 | 이 프로젝트에서 |
|---|---|---|
| C-12 | 운영 정보·제어 명령의 위변조 및 replay 공격 방지 | HMAC 서명 + 일련번호 재전송 차단 (`security.py`, 3단계) |
| C-13 | 제어 명령·파라미터의 정상 범위 식별·관리 | 수위 변화 기준선(4b, 시간당 최대 44.5cm) — 바로 이 항목의 실제 사례 |
| C-07 | 제어시스템 구성요소 시간 동기화 | 장치 NTP 동기화 (3단계, UTC 미보정 문제 해결) |
| C-30 | 침입탐지시스템 구축·보안 이벤트 모니터링 | 느린 무차별 대입 탐지(4a) + 숨은 API 탐지(6단계) |
| C-06 | 운전원별 유일 계정 부여 | 운전원 토큰이 사이트별로 분리(`operator_for`, BOLA 방지) |
| C-04 · C-05 | 용도별 계정 분리 · 최소 권한 | 장치 토큰 ≠ 운전원 토큰, 운전원은 자기 사이트만 |
| U-64 · C-16~19 | 보안 패치 적용 (서버 · 제어시스템 공통) | 8단계(공급망 SBOM) 계획과 그대로 이어짐 |

## 정직하게 미흡으로 적어야 하는 것 (좋은 발견 — 숨기면 안 됨)

| 코드 | 제목 | 실제 상태 |
|---|---|---|
| C-21 | 제어 네트워크를 업무망·인터넷과 물리적으로 분리 | **미충족** — 시연 때 cloudflared 터널로 인터넷에 노출. 상시 운영이면 전용망·VPN 필요, 지금은 "시험·시연 때만 열고 바로 닫음"으로 완화 |
| C-22 · C-23 · C-25 | 물리적 일방향 자료전달 · 무선 연결 제한 | 해당 안 됨(그런 장비 없음) — 터널 사용 자체가 이 항목들의 취지와 반대 방향 |
| C-27 · C-28 | 물리적 접근통제 | 시뮬레이터(Wokwi)라 물리 장치가 없어 **평가 불가**로 기록 (해당없음과는 다름 — "모른다"가 정직한 판정) |

## 해당없음이 많은 이유 (구조적으로 공격면이 작음)

UNIX 서비스 관리(U-34~U-63, 약 30개) 대부분은 **컨테이너에 그 서비스 자체가 없어서** 해당없음이다: Finger · r계열 · NFS · RPC · NIS · tftp/talk · 메일 · DNS · FTP · SNMP 서비스를 전혀 안 씀. 이건 점검을 안 한 게 아니라 **공격면이 애초에 작다**는 뜻이라, 보고서에는 "미점검"이 아니라 "서비스 미사용으로 해당없음"이라고 구분해서 적어야 한다 (판단 기준: U-38 DoS 취약 서비스처럼 "그 서비스를 안 쓴다"가 곧 "양호"인 항목도 있다 — 항목별 판단 기준 원문 확인 필요).

## 적용 가능 (아직 구현 안 됨, 7~9단계 후보)

| 코드 | 제목 | 비고 |
|---|---|---|
| U-65~67 | NTP · 로깅 정책 · 로그 디렉터리 권한 | 로깅은 이미 함(`logging.basicConfig`), 디렉터리 권한은 Dockerfile `chown rtu /data` 확인 필요 |
| C-02 · C-03 | 계정 사용기록 저장 · 입력값 에러 메시지 제한 | `log.warning` 이 거부 이유를 로그에만 남기는 설계(3단계)와 거의 일치 — 문서화만 하면 됨 |
| C-31~33 | 사이버 위기대응 매뉴얼 · 백업 | 학생 프로젝트 범위에서는 "매뉴얼 초안" 수준으로 축소해 기록 |
| C-50 | 허가에 의한 로직 변경 정책 | 서명된 펌웨어 업데이트(8단계 계획)와 연결 |
